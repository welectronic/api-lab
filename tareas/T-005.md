# T-005 — Documentar US3 y US4 en el README y crear .env.example

## Objetivo
Que quien llega al repo encuentre en el README el comportamiento HTTP endurecido y el endpoint de uptime, y cree su `.env` a partir de un `.env.example` sin secretos.

## Contexto (leer solo esto)
- `SPEC.md` → US3 (escenarios 5 y 6), US4 (escenario 4), RF-007, RF-009
- `ARQUITECTURA.md` → **C-003, C-004 y C-005**: documenta exactamente lo que dicen, sin inventar
- `CONVENCIONES.md` y `TROPIEZOS.md`
- Estándar: `kit/estandares/seguridad.md` (secretos)
- **Patrón de referencia a seguir:** la sección "Salud" actual de `README.md` (tabla + ejemplo JSON)

## Archivos permitidos
- Modificar: `README.md`
- Crear: `.env.example`
- **No tocar:** código (`app.js`, `routes/`, `tests/`), `.gitignore`, `package*.json`, y nunca crear ni versionar `.env`

## Contrato a respetar
- README:
  1. Tabla "Salud": agregar `GET /api/health/uptime` con ejemplo de respuesta `{"uptimeSeconds": 42}`.
  2. Nueva sección "Seguridad HTTP": los tres headers, que no se envía `X-Powered-By`, el límite de 100 kb (JSON y urlencoded) con su `413`, y los tres cuerpos de error de C-003 **textuales**.
  3. Sección "Instalación": reemplazar el bloque `.env` actual por la instrucción de copiar `.env.example` a `.env` (con el comando para PowerShell y para bash) y completar los valores.
- `.env.example` exactamente como C-005:
```
MONGO_URI=mongodb+srv://<usuario>:<password>@<cluster>/<base>
PORT=3000
```

## Criterios de aceptación
| # | Criterio | Cómo se verifica | Falla cuando |
|---|---|---|---|
| 1 | El README documenta uptime con ejemplo | lectura del diff | falta la fila o el ejemplo, o el ejemplo tiene otros campos |
| 2 | El README documenta headers, límite, 400/404/413 con los cuerpos textuales de C-003 | lectura del diff | falta uno o un texto difiere del contrato |
| 3 | La instalación usa `.env.example` | lectura del diff | sigue el bloque con valores escritos a mano, o no hay comando para copiar |
| 4 | `.env.example` tiene exactamente `MONGO_URI` y `PORT` con los valores de C-005 | `cat .env.example` | otras claves, o un valor que no sea marcador (salvo `PORT=3000`) |
| 5 | Solo archivos permitidos | `git diff --stat origin/main...HEAD` | aparece otro archivo |
| 6 | Las secciones existentes (películas, notas, uso) siguen intactas | lectura del diff | se borra o cambia algo fuera de Salud, Instalación y la sección nueva |

## Casos de abuso (obligatorio: seguridad sensible)
| # | Intento o error | Resultado esperado | Verificación |
|---|---|---|---|
| A1 | Poner en `.env.example` o en el README una cadena real de MongoDB (usuario, password, host de Atlas) | Solo marcadores `<…>`; nada que parezca credencial | `git diff origin/main...HEAD` sin `mongodb+srv://` fuera del marcador de C-005 |
| A2 | Versionar `.env` por accidente | `.env` no aparece en el diff y sigue ignorado | `git check-ignore -v .env` imprime la regla de `.gitignore`; pega la salida |
| A3 | Copiar al README valores de tu `.env` local | El README no contiene valores reales | revisión del LIDER |
