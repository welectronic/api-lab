# T-005 — Documentar US3 y US4 en el README y crear .env.example

## Objetivo
Que quien llega al repo encuentre en el README el comportamiento HTTP endurecido y el endpoint de uptime, y cree su `.env` a partir de un `.env.example` sin secretos.

## Contexto (leer solo esto)
- `SPEC.md` → US3 (escenarios 5 y 6), US4 (escenario 4), RF-007, RF-009
- `ARQUITECTURA.md` → **C-003, C-004 y C-005**: documenta exactamente lo que dicen, sin inventar
- `CONVENCIONES.md` y `TROPIEZOS.md`
- Estándar: `kit/estandares/seguridad.md` (secretos)
- **Patrón de referencia a seguir:** la sección "Salud" actual de `README.md` (tabla + ejemplo JSON)

## Archivos permitidos
- Modificar: `README.md`
- Crear: `.env.example`
- **No tocar:** código (`app.js`, `routes/`, `tests/`), `.gitignore`, `package*.json`, y nunca crear ni versionar `.env`

## Contrato a respetar
- README:
  1. Tabla "Salud": agregar `GET /api/health/uptime` con ejemplo de respuesta `{"uptimeSeconds": 42}`.
  2. Nueva sección "Seguridad HTTP": los tres headers, que no se envía `X-Powered-By`, el límite de 100 kb (JSON y urlencoded) con su `413`, y los tres cuerpos de error de C-003 **textuales**.
  3. Sección "Instalación": reemplazar el bloque `.env` actual por la instrucción de copiar `.env.example` a `.env` (con el comando para PowerShell y para bash) y completar los valores.
- `.env.example` exactamente como C-005:
```
MONGO_URI=mongodb+srv://<usuario>:<password>@<cluster>/<base>
PORT=3000
```
