# T-001 — Agregar GET /api/health con su test

## Objetivo
Que `GET /api/health` responda `200 {"status":"ok"}` y que `npm test` lo verifique sin MongoDB ni SQLite.

## Contexto (leer solo esto)
- `SPEC.md` → US1, RF-001, RF-002
- `ARQUITECTURA.md` → C-001 y C-002
- `CONVENCIONES.md`
- Estándar: `kit/estandares/seguridad.md` (§3 HTTP: los errores no exponen detalles)
- **Patrón de referencia a seguir:** `routes/sqliteRoutes.js` (router) y `app.js` (cómo se monta)

## Archivos permitidos
- Crear: `routes/healthRoutes.js`, `tests/health.test.js`
- Modificar: `app.js` (solo `require` + `app.use('/api', healthRoutes)`), `package.json` (solo agregar `"test": "node --test"` en `scripts`)
- **No tocar:** `server.js`, `config/`, `models/`, las rutas existentes, `package-lock.json`, `README.md` (es de T-002)

## Contrato a respetar
```
GET /api/health
→ 200 OK
  Content-Type: application/json; charset=utf-8
  {"status":"ok"}
```

## Criterios de aceptación
| # | Criterio | Cómo se verifica | Falla cuando |
|---|---|---|---|
| 1 | `GET /api/health` cumple el contrato (status, content-type JSON, cuerpo exacto) | `npm test` | el test no compara status 200, `content-type` que empiece por `application/json` y `deepStrictEqual` con `{status:'ok'}`; o el cuerpo tiene campos extra |
| 2 | `npm test` corre sin MongoDB ni SQLite y el proceso termina solo | `npm ci && npm test` sin `.env` | el test importa `server.js`, necesita `MONGO_URI`, queda colgado o no cierra el servidor |
| 3 | Sin dependencias nuevas | `git diff origin/main...HEAD -- package.json package-lock.json` | cambia algo distinto a la línea del script `test`, o cambia `package-lock.json` |
| 4 | Solo archivos permitidos | `git diff --stat origin/main...HEAD` | aparece cualquier archivo fuera de la lista |
| 5 | Siguen funcionando: los routers de `/api/movies` y `/api/notes` siguen montados | inspección del diff de `app.js` | se quita, reordena o altera un `app.use` existente |

## Fuera de alcance
- Consultar el estado de MongoDB/SQLite (readiness), versión o uptime.
- Tests de los endpoints existentes.
- Documentar en el README (T-002).
