## Propuestas al kit (opcional; no las apliques tú)
- En `PROTOCOLO.md` §5 / `TROPIEZOS.md` #3: `git worktree add -b <rama> origin/main` deja `origin/main` como upstream de la rama nueva, así que un `git push` sin argumentos apuntaría a `main` (y con D-5 GitHub no lo impide). Sugerencia: añadir `--no-track` al comando (`git worktree add --no-track -b <rama> ../<repo>.T-XXX origin/<rama_origen>`) y empujar con `git push -u origin <rama>`.
- El formato de activación `CHARTER: <proyecto> <ID>` espera un rol, pero el tablero indica activar con el ID de la tarea (`CHARTER: api-lab T-004`). Sugerencia: que la activación incluya ambos (`CHARTER: api-lab SENIOR-1 T-004`), para que la instancia no tenga que deducir el rol.
